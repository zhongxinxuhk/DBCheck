# DBPulse v1.0.9 升级至 v1.0.17

## 备份与回导

1. 在 v1.0.9 状态窗口使用「数据备份与恢复」导出备份 ZIP。另行保存台账 Excel 用于核对。ZIP 内的 `data/.db_key` 必须和数据库文件一起保留。
2. 停止旧服务，在独立目录准备 v1.0.17，使用状态窗口验证并导入 ZIP，然后启动。v1.0.9 的状态窗口可导出和导入备份，离线更新入口是后续版本新增的功能。导入会在 `backups/before-import-*` 下记录替换前的数据位置。
3. 核对账号、数据源、台账、巡检记录、报告、任务和规则。旧部署外部的文件仍需部署到新主机，包括 CA 证书、SSH 私钥以及 JDBC 连接串引用的文件。核对这些文件在新主机上的路径后执行连接测试。
4. 需要回导 Excel 时，在「数据库运维台账 → 更多操作 → 导入台账 Excel」上传并核对预览。相同配置项编号更新原记录，已有连接匹配和新增会分别标明。确认后资产主表、连接配置和专项明细同一事务保存，数据源缓存及主界面随之刷新。留空的密码沿用存储值。Excel 变更记录页用于查阅，完整历史随备份 ZIP 恢复。
5. 如需回退，将原版本程序与升级前的整套数据一起恢复。备份 ZIP 和含连接凭据的 Excel 应作为敏感运维文件保管。

## GBase 8a 连接

可信内网中，若 GBase 8a 实例按 Navicat 的明文配置连接，进入「数据源管理」编辑该实例，开启「允许明文直连」并保存。也可以在台账维护窗口的高级连接选项中设置。连接测试、巡检和监控读取同一选项。使用 TLS 时填写 CA 路径并关闭明文选项。v1.0.9 存量记录保留原有默认策略，待运维人员按各实例的部署方式选择。

## 告警链路

1. 监控先采集会话、慢查询、容量与性能。会话查询失败时执行数据库原生的只读探活。探活成功时实例仍计为在线，会话失败原因保留在下钻详情。探活失败才进入离线判断，采集未完成时显示待检测。首页与监控大屏使用同一可用性快照，首页另外显示已停用数量。
2. 大屏按连接利用率、剩余空间、复制延迟、锁等待生成预警和严重状态。使用 `data/dbc_config.json` 的 `notification.monitor_alert.enabled` 控制监控通知，`min_level` 可填 `warn` 或 `crit`，缺省为 `warn`。
3. 启动时首轮有效样本的异常发送汇总。随后新告警、等级变化和恢复按实例发送。同级持续期间去重。未完成或能力未知的样本留待下一次有效采集，实例停用或删除时停止跟踪。降到通知阈值以下时，通知包含当前等级。
4. 邮件与 Webhook 使用「通知配置」里的通道。投递失败记入日志，当前状态机采用进程内去重和异步发送。定时巡检任务走自己的通知设置，按巡检是否完成或失败发送报告或结果。

## 验证范围

- 使用原 v1.0.9 源码导出备份和台账，在隔离环境恢复后验证密钥、任务文件、规则、台账明细以及 PostgreSQL 17 数据源连接。回导 Excel 后核对原记录更新及数据源缓存刷新。
- 使用 Docker 的 GBase 8a 8.6.2 验证明文直连、版本识别、会话监控及吞吐计数。Oracle Database Free 23 实测会话视图权限不足时仍显示在线，认证失败时显示不可达。SQL Server 2022 实测 JDBC 加密连接及会话和性能采集。
- 使用 Mailpit 和本地 HTTP 接收端验证启动摘要、恢复和严重告警都能经 SMTP 与 Webhook 发送。生产实例的端口、账号权限和通知通道需在现场验收。
